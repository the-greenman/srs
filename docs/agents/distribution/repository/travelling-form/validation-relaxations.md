Specification: SRS 2.0-draft, data model revision 11. Part of the [SRS specification index](/llms.txt). Up: [Travelling form](/agents/distribution/repository/travelling-form.md).

An RFC-026-aware validator MUST NOT treat the following as errors when a `slice` block is present: `externalRelationRefs` UUIDs absent from the repository's tree-authoritative instance enumeration (RFC-038 [R1], not a manifest `instanceIndex`, retired per RFC-038 [R2]; I-153); absence of source packages the slice does not carry (RFC-026 [R15]), which is not reported; an incomplete container enumeration (not a manifest `containerIndex`, retired per RFC-038 [R2]; I-152); tombstoned source document entries with absent content files. Carrying packages whole makes two diagnostic classes expected absences, a slice's root identity record makes a third, and a root member that anchors no container makes a fourth: all four MUST be reported at severity info, not warning or error (RFC-026 [R17], Change E item 5). They are a Composition section source naming a Container that is not in the slice, a Composition whose `rootTypeRefs` match no Container anchor in the slice, Invariant I-81 (the root identity record is not a `purpose` record), because a slice says what it is through its identity record, and Invariant I-82 (a root container member that anchors no container, as a document-state or comment member of a content slice does), because a slice is a bundle (Revision 10, owner ruling 2026-10-05). Every other diagnostic keeps its severity. Dangling edges in the relations collection, unresolvable `typeId`/`fieldId` references, any unresolved reference from one carried definition to another, and instance schema validation errors remain errors regardless of slice status.
